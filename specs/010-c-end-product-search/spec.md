# Feature Specification: C端商品搜索功能

**Feature Branch**: `010-c-end-product-search`

**Created**: 2026-06-27

**Status**: Draft

**Input**: "C端商品搜索功能，你按你的想法来开发需要什么。"

## User Scenarios & Testing

### User Story 1 — 关键词搜索（Priority: P1）🎯 MVP

用户在商品列表页顶部的搜索框输入关键词（如"牛奶"、"iPhone 壳"），系统根据商品名称和副标题模糊匹配，返回相关商品列表。

**Why this priority**: 搜索是电商最基础的功能。当前只有按分类筛选，用户想找特定商品只能一个一个翻。

**Independent Test**: 打开商品列表，搜索"牛奶"，返回所有名称或副标题包含"牛奶"的在售商品。

**Acceptance Scenarios**:

1. **Given** 用户在搜索框输入"牛奶"，**When** 点击搜索按钮，**Then** 返回名称或副标题包含"牛奶"的商品列表，按综合排序
2. **Given** 用户搜索的关键词没有匹配商品，**When** 搜索完成，**Then** 返回空列表，显示"未找到相关商品"提示
3. **Given** 用户搜索关键词为空，**When** 点击搜索，**Then** 返回全部在售商品列表（等同进入分类页面）

---

### User Story 2 — 搜索筛选与排序（Priority: P1）

搜索结果显示后，用户可按价格区间筛选，按价格从低到高/从高到低、销量、最新上架排序。

**Why this priority**: 搜索结果多时用户需要缩小范围和排序来找想要的商品。

**Independent Test**: 搜索"牛奶"后，选择 1-50元价格区间，按销量排序，返回符合条件的结果。

**Acceptance Scenarios**:

1. **Given** 搜索结果已展示，**When** 用户选择价格区间（如拖拽滑块或输入最低/最高价），**Then** 结果按价格区间过滤
2. **Given** 搜索结果已展示，**When** 用户点击"销量优先"排序按钮，**Then** 结果按销量从高到低排列
3. **Given** 搜索并筛选后的结果很少，**When** 用户清空筛选条件，**Then** 恢复为全部搜索结果

---

### User Story 3 — 分类+搜索组合（Priority: P2）

用户在某个分类下（如"饮料"分类内可以再搜"可乐"），搜索结果限制在该分类中。

**Why this priority**: 用户在逛分类时想精确找某个商品，组合筛选减少翻页。

**Independent Test**: 先点进"饮料"分类，再搜索"可乐"，结果只展示饮料分类下的可乐商品。

**Acceptance Scenarios**:

1. **Given** 用户已在某个分类页面，**When** 在分类内搜索关键词，**Then** 结果限制在该分类且名称匹配关键词的商品
2. **Given** 分类+搜索后无结果，**When** 用户清空关键词，**Then** 恢复为该分类的全部商品

### Edge Cases

- 关键词含特殊字符或 emoji：系统应正确处理，不做特殊过滤
- 关键词前后空格：应 trim 后再搜索
- 搜索频率过快：前端应做 500ms 防抖，不对后端造成压力
- 商品名含英文大小写：MySQL 默认不区分大小写，无需额外处理

## Requirements

### Functional Requirements

- **FR-001**: 系统必须支持用户输入关键词搜索商品名称和副标题，返回匹配的在售商品列表
- **FR-002**: 搜索结果必须支持按价格区间过滤（最低价/最高价可选）
- **FR-003**: 搜索结果必须支持排序方式：综合排序（默认）、价格升序、价格降序、销量优先、最新上架
- **FR-004**: 系统必须支持分类+关键词的组合搜索
- **FR-005**: 搜索结果必须分页返回，每页数量可配置
- **FR-006**: 关键词为空时返回全部在售商品（等同商品列表接口）
- **FR-007**: 搜索结果必须只包含状态为上架的商品

### Key Entities

- **Product（商品SPU）**: 已有实体。搜索涉及字段：`name`（商品名称）、`subtitle`（副标题/卖点）、`min_price`（最低售价）、`max_price`（最高售价）、`sales`（销量）、`status`（上架/下架）、`category_id`（分类ID）
- **Category（商品分类）**: 已有实体。用于分类+搜索组合

## Success Criteria

- **SC-001**: 用户从输入关键词到看到搜索结果，不超过 2 秒（1000条商品以内）
- **SC-002**: 搜索结果的排序和筛选在 1 秒内响应
- **SC-003**: 搜索结果准确匹配用户意图，无无关商品混入

## Assumptions

- 商品数量在 1000 级别以内，MySQL LIKE 查询足够，无需引入 Elasticsearch
- 用户习惯先选分类再搜关键词，或直接搜
- 价格区间由前端传递两个参数（minPrice/maxPrice），后端 SQL 层面过滤
- 搜索接口对未登录用户也开放（无需 `@RequiresLogin`）
- 后续商品量增长后可考虑 MySQL FULLTEXT 索引或 Elasticsearch 迁移，当前不做过度设计
